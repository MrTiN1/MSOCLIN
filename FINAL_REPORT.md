# Итоговый отчёт — 10 ноября 2026 года

Проект создан в `/workspace/work/mos-clean/app`. Это работающий frontend и backend, а не статический макет. Production-деплой и изменение DNS не выполнялись.

## 1. Что реализовано

- Next.js App Router, React, TypeScript, Tailwind, Radix/shadcn-компоненты, Lucide, Motion, React Hook Form, Zod, date-fns.
- Главная в тёмной палитре и двухколоночной композиции предоставленного референса, адаптивная навигация, карточки услуг, этапы, калькулятор, FAQ, акции и контакты.
- Все запрошенные основные маршруты и 14 страниц услуг. Категории, поиск, реальные профильные прайсы, предварительные оценки.
- Четырёхшаговый калькулятор с данными и правилами из PostgreSQL. Учёт количества, материала, допуслуг и минимального выезда. Неоднозначные позиции требуют консультации.
- Серверный календарь по отдельным графикам бригад, прошедшие/занятые дни, перерывы, дорога, длительность и ручные блокировки. Модальное окно свободного времени. Московская временная зона.
- Атомарная запись в PostgreSQL; транзакционная блокировка и GiST EXCLUDE защищают от пересечения интервалов. Две бригады принимают две записи на один слот; третья получает конфликт. Идемпотентность, временные резервы, освобождение времени после отмены/истечения, номер заявки и защищённый статус.
- CRM с безопасными сессиями: Dashboard, заявки, согласованная сумма, статусы, перенос/бригада, услуги заказа, комментарии и история; календарь день/неделя/месяц; графики и выходные; управление услугами, ценами, FAQ, акциями, отзывами, портфолио, контактами и основными текстами.
- Telegram Bot API, durable outbox, повторная доставка, защищённые callback-кнопки и проверка разрешённых менеджеров/чата.
- Сохранение обратных звонков в БД, серверная валидация, телефонная маска, согласие, защита Origin, лимиты запросов. Защищённая загрузка и перекодирование фотографий в Vercel Blob.
- Метаданные, canonical, Open Graph, JSON-LD, sitemap, robots, локальные шрифты, оптимизация изображений, optional Яндекс Метрика без ПДн.

## 4. Какие внешние настройки нужны

Production PostgreSQL, APP_URL и AUTH_SECRET; собственная учётная запись администратора; реальные бригады, графики, перерывы и длительности. Для уведомлений — токен бота, разрешённый chat ID, ID менеджеров и webhook secret; для загрузок — Vercel Blob. Для аналитики — ID Метрики. Перед запуском требуется согласование юридических реквизитов, политики обработки/хранения данных и актуального прайса.

## 5. Что ещё не подключено

- Реальная доставка Telegram без предоставленных ключей не проверена; код и обработчики реализованы, заявки сохраняются независимо от неё.
- Vercel и production-БД не подключены; деплой запрещён до отдельного подтверждения владельца.
- Собственные разрешённые фотографии компании и проверенные тексты отзывов не предоставлены. Функции галереи/слайдеров/публикации реализованы, исходный реестр кейсов и отзывов пуст. Показаны ссылки на официальные площадки, стоки подписаны как иллюстрации.
- Реальное расписание компании не подтверждено. Стандартный seed создаёт неактивные бригады. Текущая локальная среда имеет тестовый график для проверки; переносить его в production без проверки нельзя.
- Предпросмотр Sites недоступен из-за отсутствующего preview relay. Проверка выполнена локальным Chromium. Каталог вывода `/codex/.../output`, заданный для этого чата, отсутствует и недоступен для создания в выбранном executor; файлы и архив оставлены в доступной рабочей папке.

## 6. Как запустить

Из каталога проекта:

```bash
npm ci
cp .env.example .env
# Заполнить PostgreSQL, APP_URL, AUTH_SECRET; создать отдельный пароль администратора.
npm run db:deploy
npm run db:seed
npm run admin:create
npm run dev
```

Адрес в запущенной среде: `http://localhost:3000`, CRM — `/admin`. Полные инструкции PostgreSQL, Telegram, Vercel и резервного копирования находятся в README.md. Секреты, локальные пароли, БД и browser traces в архив исходников не включаются.
