# МОС ХИМЧИСТКА

Полноценный Next.js-проект с публичным сайтом, расчётом цены, PostgreSQL-бронированием и CRM. Production не публиковался, DNS не менялся.

## Запуск

Требуется Node22.12+ (проверено на24), npm, PostgreSQL15+ с btree_gist. Код совместим с Vercel Node runtime.

```bash
npm ci
cp .env.example .env
# Заполните DATABASE_URL, POSTGRES_PASSWORD, AUTH_SECRET и APP_URL.
docker compose up -d postgres  # если нет своего PostgreSQL
npm run db:deploy
npm run db:seed
npm run admin:create         # ADMIN_EMAIL + ADMIN_PASSWORD (14+ символов) в окружении
npm run dev
```

Сайт: http://localhost:3000, CRM: /admin. Нет учётных данных по умолчанию. После одноразового создания администратора уберите ADMIN_PASSWORD из окружения. AUTH_SECRET создайте `openssl rand -hex 48`. Seed безопасно добавляет недостающие справочники, не затирает изменения оператора. Не запускайте refresh-local-content.ts на реальных данных.

По умолчанию две стартовые бригады **неактивны**, поэтому публичных свободных слотов нет, пока оператор не настроит их реальный график в CRM. Для локальной проверки можно установить LOCAL_DEMO_SCHEDULE=true перед первым seed. Это локальные тестовые часы9–19, перерыв13–14, дорога30минут, а не подтверждённое расписание компании. Для существующей БД включайте/выключайте бригады в CRM: повторный seed не меняет их состояние.

## Страницы и возможности

`/` — главная по композиции предоставленного референса; `/services` и `/services/[slug]` — каталог, категории, поиск, профильные цены и SEO; `/calculator` —4шага и серверная оценка; `/booking` — параметры, календарь из БД, модальное окно слотов, контакты, номер заявки и защищённый статус; `/portfolio` — категории, before/after-слайдеры и полноэкранное окно для опубликованных владельцем работ; `/about`, `/reviews`, `/contacts`, `/privacy`; `/admin` — защищённая CRM.

В CRM: статусы, согласованная цена, назначение/перенос бригады, изменение услуги и параметров, внутренние комментарии, история; календарь день/неделя/месяц; график и перерывы по дням недели, выходные, ручные блокировки; услуги, варианты цен, категории, FAQ, акции, отзывы, портфолио, основные тексты и контакты. Скрытие вместо опасного удаления контента. Dashboard считает заявки по статусам и выручку только выполненных.

Цены и факты проверены на https://mos-drycleaning.ru; подробности и расхождения в CONTENT_AUDIT.md. Все суммы предварительные. Неоднозначные услуги требуют консультации; скидки не применяются автоматически без условий. В публичной галерее нет выдуманных работ, в отзывах — выдуманных клиентов. До предоставления разрешённых материалов есть ссылки на оригинальные площадки.

## PostgreSQL

Создайте пустую БД и пользователя с разрешением CREATE EXTENSION btree_gist (или попросите DBA включить расширение). Укажите строку подключения в DATABASE_URL. Для Vercel подойдёт PostgreSQL Neon/Supabase с совместимым TCP-подключением и пулом; миграции запускайте через прямое подключение в отдельном этапе релиза. `npm run db:deploy` применяет миграцию и EXCLUDE-ограничение, `db:seed` добавляет начальные данные. Не используйте `prisma db push` вместо миграций: оно не создаст вручную написанное ограничение пересечений.

Значения времени — UTC timestamptz, рабочая зона — Europe/Moscow. Политика резерва, шаг, горизонт и минимальное время до начала настраиваются в CRM. Перед публикацией проверьте длительности всех услуг, бригады и расписания. Для больших уборок длительность и состав бригады нужно согласовать отдельно.

## Telegram

Через переменные окружения задайте TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, TELEGRAM_ADMIN_IDS (список числовых user ID через запятую), TELEGRAM_WEBHOOK_SECRET (случайный ASCII/hex). Бот должен иметь доступ **только к разрешённому служебному чату**. Задайте webhook Bot API `setWebhook` на `https://ваш-домен/api/telegram/webhook` с параметром `secret_token`; передавайте токен через защищённые настройки/скрипт, не сохраняйте в репозитории или истории shell.

Уведомление включает данные заказа и кнопки «Подтвердить», «Отклонить», «Открыть заказ». Callback проверяет секрет Telegram, chat ID и ID менеджера. Без конфигурации заявки всё равно сохраняются; CRM показывает UNCONFIGURED. После настройки выполните `npm run notifications:retry`. Для cron задайте CRON_SECRET: endpoint требует `Authorization: Bearer ...`. vercel.json содержит ежедневный retry, совместимый с ограниченным cron-тарифом; для более частых повторов используйте доступный вашему тарифу scheduler. Персональные данные в другие чаты не отправляются.

## Фотографии и аналитика

Создайте Vercel Blob store и задайте BLOB_READ_WRITE_TOKEN. Без ключа загрузка возвращает понятную ошибку настройки. Фото до5МБ, JPEG/PNG/WebP; сервер проверяет, удаляет метаданные, ограничивает размер. Публикуйте портфолио только после подтверждения прав и согласия клиентов. Стоки Unsplash используются как иллюстрации, а не кейсы компании; источники и лицензия записаны в CONTENT_AUDIT.md. Manrope распространяется по OFL, текст в public/fonts/OFL.txt.

Метрика включается NEXT_PUBLIC_YANDEX_METRIKA_ID. События: service_selected, calendar_opened, date_selected, time_selected, booking_submitted, booking_success, callback_success. Имя, телефон, адрес и комментарии в аналитику не отправляются, Вебвизор отключён. Перед включением аналитики согласуйте политику согласий с владельцем.

## Проверки

```bash
npm run typecheck
npm test
# Создайте ОТДЕЛЬНУЮ PostgreSQL-базу, имя оканчивается _test:
# createdb mos_test
# Укажите TEST_DATABASE_URL в .env
node --import tsx scripts/prepare-test-db.ts
npm run test:integration
npm run build
```

Vitest: цена, проценты, минимальный выезд, московская дата, интервалы, валидация, пароли. Интеграционные тесты в отдельной БД: одновременные запросы,2бригады, интервал чистки+дороги, перерывы, отмена, истечение резерва, перенос, выходной, блокировка, идемпотентность и прямое нарушение EXCLUDE. Тестовые команды отказываются работать с DATABASE_URL без суффикса _test.

Playwright: установите Chromium (`npx playwright install chromium`) либо укажите CHROMIUM_PATH. Запустите отдельный dev-сервер **с DATABASE_URL=TEST_DATABASE_URL**, затем `node --import tsx scripts/prepare-e2e.ts`, затем `npm run test:e2e`. prepare-e2e создаёт случайные тестовые учётные данные в игнорируемом `.env.e2e`, не выводя пароль. Укажите E2E_BASE_URL при другом адресе. Автотесты включают настоящую запись в БД, подтверждение/отмену в CRM, формы, права доступа, калькулятор, изменение контента и ширины320–1920. Не направляйте тесты на production.

## Vercel

Проект подготовлен, деплой требует отдельного подтверждения владельца.

1. Импортируйте исходники в приватный Git-репозиторий, затем в Vercel; framework Next.js. Настройки в vercel.json.
2. Подключите production PostgreSQL и Blob. Заполните DATABASE_URL, APP_URL=https://ваш-домен, AUTH_SECRET и остальные нужные переменные. TRUST_PROXY=true только если платформа перезаписывает IP-заголовок. LOCAL_DEMO_SCHEDULE=false.
3. На пустой БД примените миграции, seed и отдельно создайте администратора. Не запускайте тестовые команды на этой БД.
4. Настройте реальные бригады, графики и длительности; перепроверьте опубликованные прайсы и акции. Добавьте юридические реквизиты в политику данных, согласуйте сроки хранения и обработку ПДн.
5. Выполните `npm run build`. После разрешённого деплоя проверьте HTTPS, APP_URL, CRM, новую тестовую заявку с согласованными контактами, Telegram и публикацию фотографий.

## Резервные копии

Включите автоматические backups/PITR у провайдера PostgreSQL. Храните зашифрованные копии отдельно от сервера и ограничьте доступ. Для ручной копии используйте `pg_dump --format=custom --file=backup.dump "$DATABASE_URL"` в защищённом окружении. Проверяйте восстановление `pg_restore` на отдельной пустой БД. Не применяйте восстановление к production без подтверждения. Отдельно резервируйте Blob-объекты и конфигурацию без раскрытия секретов. Определите срок удаления резервных копий с учётом политики персональных данных.

## Структура

- app/ — страницы, SEO и API.
- components/ — интерфейс, календарь, калькулятор, CRM; ui/ — Radix/shadcn-компоненты.
- lib/ — Prisma, цены, интервалы, транзакции заказов, сессии, валидация, Telegram.
- prisma/schema.prisma и migrations/ —21модель и SQL-ограничения; seed.ts — проверенные справочники.
- scripts/ — безопасное создание администратора, тестовые БД и повтор уведомлений.
- tests/ — Vitest, PostgreSQL integration и Playwright.
- public/ — локальные лицензированные иллюстрации, шрифты, favicon.
- CONTENT_AUDIT.md, ARCHITECTURE.md, IMPLEMENTATION_PLAN.md, .env.example, compose.yml, vercel.json.

## Что требует владельца до запуска

Production PostgreSQL, секреты и администратор; реальные бригады/расписания/длительности; Telegram и Blob; фотографии с правами, тексты отзывов с источниками; юридические реквизиты и сроки хранения; подтверждение неоднозначных единиц прайса. До этих настроек проект нельзя считать подключённым к реальной операционной системе компании. Реальная Telegram-доставка и Vercel-деплой без ключей не проверялись.
